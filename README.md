# 隱碼防偽 · 掃碼驗證系統

一套對抗「掃描複製」的實體防偽方案。標籤外觀是一顆普通 QR，防偽訊號藏在碼面模塊的
色彩微差裡；掃碼後的驗證頁用手機相機拍攝標籤、量測隱碼是否存活，依結果決定是否放行。

這是防偽驗證端的**概念驗證示範站**，重點在驗證邏輯與威脅模型的設計。

👉 **[開啟示範站](https://casperjian.github.io/qr-verify-demo/)**

## 威脅模型

防的是最常見、成本最低的仿冒手法：**攻擊者拿到真品，把 QR 直接掃描 / 拍照複製**貼到假貨上。

- 一般 QR 碼可被無損複製 → 光靠 QR 內容無法辨真偽
- 本方案在碼面模塊嵌入肉眼難辨的**色彩微差隱碼**；複製流程（掃描、重印）會破壞這層微差
- 因此攻擊者能複製「看得到的 QR」，卻無法複製「看不到的隱碼」

設計時假設攻擊者知道機制存在，安全性不依賴機制保密，而依賴**隱碼在複製後不可還原**。

## 兩段式驗證

刻意拆成兩關，兩關都過才放行：

**第 1 步 — 掃碼驗簽**　手機原生相機掃碼落地驗證頁 → 解開不透明短碼 → 驗序號簽章。
不過即停止（擋掉竄改序號 / 偽造網址）。

**第 2 步 — 拍攝量測**　由使用者主動按鈕開相機（避免一載入就跳權限）→ 定位 QR →
四角透視校正 → 逐模塊取樣 → 量測隱碼是否存活。

## 判定方法：為什麼用「符號一致率」而不是「訊號強度」

碼面切成 4×4 格，四層隱碼共 64 格，每格各自算「A 組平均 − B 組平均」。

關鍵設計決定：**主指標是符號（正負）一致率，不是訊號強度。**

- 印刷批次、光線、相機會改變訊號的**強度**，但不會改變**符號**方向
- 真品：每格符號穩定朝設計方向 → 一致率極高
- 複製品：隱碼被抹除，只能亂猜 → 符號正確率期望值就是 **50%**（等於擲硬幣）

這個選擇讓判定對「印刷色偏 / 拍攝環境」有高容忍度，同時對「複製攻擊」保持敏感。

| 條件 | 判定 |
|---|---|
| 一致率 ≥95% 且訊號過底線 | **PASS** |
| 一致率 ≥85% 且強度達標 | **PASS** |
| 一致率 ≤65% | **FAIL**（疑似複製品） |
| 其餘 | **HOLD**（建議重拍） |

門檻可在頁面現場校定，設定存於本機瀏覽器。

## 安全設計細節

- **不透明短碼**：網址不外露 `序號.簽章` 結構，避免攻擊者從 URL 推導格式
- **簽章先行**：先驗簽再進拍攝階段，擋掉序號竄改
- **前端僅為 PoC**：判定邏輯目前在前端，正式版的驗證與資料發放會移至伺服器端，
  避免用戶端繞過；標籤生成端與印刷參數不在本 repo

## 現階段限制（誠實揭露）

- 判定在前端執行，僅供概念驗證，不具生產級抗繞過能力
- 頁面上的品牌與產品資料皆為示範內容，非真實紀錄
- 尚未做大量不同印刷批次 / 光源的準確率統計（PASS/FAIL 門檻為初步校定）
