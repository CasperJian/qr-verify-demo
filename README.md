# 隱碼防偽 · 掃碼驗證系統

一套對抗「掃描複製」的實體防偽方案。標籤外觀是一顆普通 QR，防偽訊號藏在碼面模塊的
色彩微差裡；掃碼後的驗證頁用手機相機拍攝標籤、量測隱碼是否存活，依結果決定是否放行。

這是防偽驗證端的**概念驗證示範站**，重點在驗證邏輯與威脅模型的設計。

👉 **[消費者驗證頁](https://casperjian.github.io/qr-verify-demo/)**　·　**[品牌端管理台](https://casperjian.github.io/qr-verify-demo/console.html)**

管理台是**介面與資料流的示範**，與驗證頁**刻意不串接**：資料存在瀏覽器本機、清單中的
驗證次數與地點為模擬資料。現場產生的序號、HMAC 簽章與 QR 都是實際計算的，掃碼可進到
驗證頁並通過簽章檢查；但**防偽層的判定不在管理台驗證**——防偽訊號是印刷時加上去的，
螢幕上沒有。那部分的證明在生成端的翻印攻擊模擬與實體標籤實測。

## 威脅模型

防的是最常見、成本最低的仿冒手法：**攻擊者拿到真品，把 QR 直接掃描 / 拍照複製**貼到假貨上。

- 一般 QR 碼可被無損複製 → 光靠 QR 內容無法辨真偽
- 本方案在碼面模塊嵌入肉眼難辨的**色彩微差隱碼**；複製流程（掃描、重印）會破壞這層微差
- 因此攻擊者能複製「看得到的 QR」，卻無法複製「看不到的隱碼」

設計時假設攻擊者知道機制存在，安全性不依賴機制保密，而依賴**隱碼在複製後不可還原**。

## 兩段式驗證

刻意拆成兩關，兩關都過才放行：

**第 1 步 — 掃碼驗簽**　手機原生相機掃碼落地驗證頁 → 解開不透明短碼 → 驗序號簽章。
不過即停止（擋掉竄改序號 / 偽造網址）。

**第 2 步 — 拍攝量測**　由使用者主動按鈕開相機（避免一載入就跳權限）→ 定位 QR →
四角透視校正 → 逐模塊取樣 → 量測隱碼是否存活。

## 判定方法：為什麼用「符號一致率」而不是「訊號強度」

碼面切成 4×4 格，四層隱碼共 64 格，每格各自算「A 組平均 − B 組平均」。

關鍵設計決定：**主指標是符號（正負）一致率，不是訊號強度。**

- 印刷批次、光線、相機會改變訊號的**強度**，但不會改變**符號**方向
- 真品：每格符號穩定朝設計方向 → 一致率極高
- 複製品：隱碼被抹除，只能亂猜 → 符號正確率期望值就是 **50%**（等於擲硬幣）

這個選擇讓判定對「印刷色偏 / 拍攝環境」有高容忍度，同時對「複製攻擊」保持敏感。

| 條件 | 判定 |
|---|---|
| 一致率 ≥95% 且訊號過底線 | **PASS** |
| 一致率 ≥85% 且強度達標 | **PASS** |
| 一致率 ≤65% | **FAIL**（疑似複製品） |
| 其餘 | **HOLD**（建議重拍） |

門檻可在頁面現場校定，設定存於本機瀏覽器。

## 中央客製圖

QR 中央可以蓋上品牌 logo（7×7／9×9／11×11 個模塊）。上傳的圖會自動置中裁方、
縮到 320px 存在本機瀏覽器，一個品牌存一張。

放圖會蓋掉一部分資料模塊，能不能放多大取決於 QR 的模塊數，而模塊數又取決於網址長度——
**網址越短、模塊越少，同樣尺寸的圖佔比反而越大、越容易蓋掉資料**。所以管理台不寫死上限，
而是每次產生後用驗證端同一支 jsQR **實際解碼三種解析度**：

| 自檢結果 | 意思 |
|---|---|
| 可正常掃描（3/3） | 三種解析度都解得出，可以送印 |
| 邊界（1–2/3） | 時通時不通，建議中央圖改小一級 |
| 掃不出來（0/3） | 蓋掉太多資料，必須改小 |

以目前的驗證站網址（73 字元、QR 版本 5）實測：7×7／9×9／11×11 皆 3/3 通過，13×13 解不出。

驗證端以亮度與色度離群**自動排除**中央圖那塊區域，不需要知道圖形位置或形狀，
因此放 logo 不影響防偽層判定。彩色或高飽和的圖最理想（排除得乾淨）；純黑白 logo
反而容易與碼面模塊混淆。

## 層組合實驗模式（`?layers=`）

四層隱碼可以分別開關，用來做實印測試——例如印一批只帶某幾層的標籤，
比較不同翻印設備對「深模塊」與「淺模塊」各殺得多乾淨，據此決定量產要開哪幾層。

驗證端**不知道**某張標籤帶了哪幾層（這是隱蔽性的一部分），未帶碼的層只能亂猜、
會把一致率拉向 50%。所以實驗時要明確指定只判哪幾層：

| 網址 | 只判定 |
|---|---|
| [`?layers=1111`](https://casperjian.github.io/qr-verify-demo/?layers=1111) | 四層全判（等同不帶參數） |
| [`?layers=1100`](https://casperjian.github.io/qr-verify-demo/?layers=1100) | 只判兩條深模塊層 |
| [`?layers=0011`](https://casperjian.github.io/qr-verify-demo/?layers=0011) | 只判兩條淺模塊層 |
| [`?layers=1000`](https://casperjian.github.io/qr-verify-demo/?layers=1000) | 只判第一層 |

四位數依序對應四條層，`1` 開 `0` 關。不帶這個參數就是四層全判（正式驗證的行為）。

無論判定範圍如何，**四層一律全部量測並顯示分析**——不計入的層照樣列出分離量與符號一致率，
只是標示「不計入判定」。這樣既不會誤判，也看得到每一層的實際狀況。

- 帶 `?layers` 時頁面頂端會出現紅色警告橫幅，**明示判定結果不代表該標籤是真品**
- 參數**只作用於當次載入**，不會覆寫校定面板存在本機的預設值
- **正式驗證一律使用不帶參數的網址**（四層全判）

判定規則隨之調整為「納入判定的層方向全部正確，且僅允許一層強度未達門檻」——
四層時與原規則完全相同。

## 安全設計細節

- **不透明短碼**：網址不外露 `序號.簽章` 結構，避免攻擊者從 URL 推導格式
- **簽章先行**：先驗簽再進拍攝階段，擋掉序號竄改
- **前端僅為 PoC**：判定邏輯目前在前端，正式版的驗證與資料發放會移至伺服器端，
  避免用戶端繞過；標籤生成端與印刷參數不在本 repo

## 現階段限制（誠實揭露）

- 判定在前端執行，僅供概念驗證，不具生產級抗繞過能力
  （`?layers=` 實驗模式因此不構成額外弱點：前端判定本來就可由原始碼繞過，
  該模式只是把既有的除錯開關做成網址參數，並加上明顯警告）
- 頁面上的品牌與產品資料皆為示範內容，非真實紀錄
- 尚未做大量不同印刷批次 / 光源的準確率統計（PASS/FAIL 門檻為初步校定）
